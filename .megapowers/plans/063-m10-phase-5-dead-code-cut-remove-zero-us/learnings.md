# Learnings — Phase 5 Dead-Code Cut

- **A single decision matrix beats N parallel asserts.** Hoisting per-tool keep/delete decisions into `test/phase5-decision-matrix.ts` and rewriting `extension-tool-descriptions`, `token-tracker-wiring-check`, `extension-devmode-tools`, `token-tracker-all-tools`, and `token-tracker-naive-files` to read from it removed an entire class of "docs vs registration vs assertion" drift. Worth doing earlier in similar surface cuts.
- **"Aesthetic cleanup" is the failure mode to guard against.** Writing the telemetry window, per-tool counts, and Phase 3 pick-rate re-check into `summary.md` before any code change forced every removal to point at its own zero-count entry. Without that gate it would have been easy to sneak in a "looks unused, probably fine" deletion.
- **Surface tests should assert by name, not by count.** The phase5 surface tests check that a removed tool name is not present — they do not hard-code "expect 3 tools". This makes the suite stable when a future phase adds a new tool without touching the Phase 5 guarantees.
- **Even fully-removed tools need a guard test.** Adding `phase5-*-surface.test.ts` per removed tool — including under `CODEGRAPH_DEVMODE=1` — means a future "let's restore graph_query" change has to either flip the decision matrix on purpose or break a named test, not silently re-register.
- **External evidence belongs in the artifact, not in chat.** Putting the observation window, telemetry counts, and pick-rate re-check directly in `summary.md` (and not just in conversation) made the verify phase mechanical: every acceptance criterion mapped to a `grep` or a small `bun -e` consistency script.
- **Verification limitations are a deliverable.** Recording explicitly that `gh_status` could not retrieve live PR metadata for Phase 3/4 — and that local git history was used as the primary source — kept reviewers from having to re-run that lookup themselves and made the gap auditable.
- **The smallest helpful future improvement:** capture telemetry counts in a checked-in JSON next to the decision matrix, so future phases can diff "was zero, is now non-zero" mechanically instead of reading prose.
