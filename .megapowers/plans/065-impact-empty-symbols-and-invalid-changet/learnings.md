# Learnings — Issue 065

- TypeBox at the MCP surface is not a substitute for runtime input validation in the underlying TypeScript functions. Direct callers (tests, future integrations, CODI) bypass it entirely, so each public function needs its own guards even when the wrapping schema looks tight.
- "Empty Trust header body" is indistinguishable from "no dependents found" in this codebase. Whenever a tool's empty-result and empty-input paths share a render, the input path needs its own diagnostic kind so agents can tell them apart.
- A `null` fallthrough in a discriminator like `classify()` is a silent input-validation hole, not a defensive default. The original `return null` was meant for the legitimate `"addition"` case but doubled as a swallow for unknown literals — splitting "known but ignored" from "unknown" should be done at the boundary, not inside the walker.
- Two-layer validation is worth the duplication: a loud Trust-header diagnostic at the public tool entry, plus a defense-in-depth guard inside the internal helper. The internal guard caught the missed acceptance criterion when verify reran the reproduction directly against `collectImpact()`.
- A first verify pass found criterion #3 still failing because the implementation only validated `changeType` at `impact()`, not at `collectImpactDetails()`. Verifying directly against the internal API (not just the tool wrapper) is what surfaced it; running the original reproduction script unchanged is more trustworthy than relying on the regression test alone.
- Choosing "throw" vs "silent `[]`" for the internal empty-symbols path was a real design decision the spec flagged for plan review. We kept silent `[]` for empty/undefined symbols (matches existing direct-caller contract) but throw for invalid `changeType` (no legitimate "do nothing" interpretation). Document those design splits in the plan; they are not obvious from the acceptance criteria alone.
- A shared `VALID_CHANGE_TYPES` constant + `isValidChangeType` type guard + `formatInvalidChangeTypeMessage` formatter kept the diagnostic copy in sync between the tool entry and the internal helper. Worth doing whenever the same validation has to fire at multiple layers.
