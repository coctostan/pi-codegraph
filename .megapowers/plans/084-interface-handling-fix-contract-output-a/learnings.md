# Learnings — #084 Interface Contract Output & False Implements Edges

- **Asymmetric extraction creates asymmetric bugs.** `extractClassSignature` already walked the class body to grab the constructor signature; `extractInterfaceSignature` never walked the interface body at all. The inconsistency wasn't visible until `symbol_graph --include contract` was exercised on an interface. Lesson: when adding body-inspection logic to one symbol kind, audit peer kinds (function, class, interface, module) for the same gap immediately.

- **"Stricter check exists in fallback path" is a maintenance hazard.** The `classImplementsInterface` declaration guard was present in `addFallbackImplementations` but absent in the LSP-success path. Both paths write the same `implements` edge type; the trust-but-don't-verify pattern in the hot path silently produced false positives. Lesson: when a fallback path is stricter than the primary path, that's an inversion — the primary path should be at least as strict.

- **LSP `implementations()` is not the same as `implements` clause presence.** The LSP returns every location where a type is "implemented", which includes return-type usages, type assertions, and structural matches — not just class declarations. Treating every returned location as a declaration-level `implements` relationship is fundamentally wrong. Lesson: LSP semantic queries need post-filtering against the source declaration; they should be used as hints, not ground truth.

- **Stored signatures are a cheap secondary index.** Using the already-stored `class Foo implements Bar` signature string as the `classImplementsInterface` ground truth avoided a file read in the hot path, handled the in-memory test cases without a real filesystem, and made the check deterministic. Lesson: `signature` field is useful beyond the contract renderer — it's queriable metadata.

- **Source-file fallback in the renderer is a good safety net.** The two-layer approach in `renderSymbolContractBody` (try the stored multiline signature first, fall back to reading the source file) means nodes indexed before this fix (with only the header stored) still render correctly as long as the source file is present. Lesson: contract rendering should gracefully degrade; prefer stored data but keep a source-read escape hatch.

- **Repro test + unit test is the right pairing.** The `repro-084-interface-handling.test.ts` file captured the exact production scenario end-to-end; the updated unit fixtures in `tool-symbol-graph-lsp.test.ts` anchored the individual function contracts. Together they caught both bugs in isolation and as an integrated flow. Lesson: for pipeline bugs (indexing → storage → rendering), both a unit test at the broken layer and an integration test at the tool output level are needed.

- **`syncDeclaredImplementations` cleanup closes the staleness gap.** Refactoring the reconciliation loop into `syncDeclaredImplementations` and calling it on every `resolveImplementations` invocation (not just first-run) means stale false-positive edges are pruned automatically when re-indexed nodes change their declaration. Lesson: edge reconciliation should be a continuous operation, not just a one-time write.
